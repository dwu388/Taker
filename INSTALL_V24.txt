V24 INSTALLATION / PRODUCTION RESEARCH COLLECTION

Windows:
  1. Run setup_v24.bat
  2. Keep Axiom open in an interactive desktop session for clipboard collection.
  3. Configure the Axiom Migrated view to expose tokens through 25 hours.
  4. Run run_axiom_once.bat once as a smoke test.
  5. Run collection_status.bat and require ready_to_collect=true.
  6. Start/resume lossless one-minute collection and gated model/policy maintenance
     with run_axiom_loop.bat.

run_axiom_loop.bat is the research-learning command. It attempts the official V24
forecast bootstrap/maintenance, rolling-origin policy cross-fit, and policy
training pipeline at startup and every 24 hours. Readiness and one-use promotion
gates remain authoritative; insufficient evidence is a reported no-op, not a
reason to stop collection. Clipboard payloads continue entering the durable
learning queue while training runs and are ingested in order afterward.

run_paper_loop.bat is the execution command. It consumes the current forecast and
policy champions but never trains or promotes them. Stop one launcher before
starting the other because both own the clipboard collector for the canonical DB.

Active lifecycle contract:
  prediction horizon:       1440 minutes / 24 hours
  Axiom viewing window:     1500 minutes / 25 hours
  natural age-out guard:    1440 minutes / 24 hours
  view-only safety buffer:    60 minutes / 1 hour

The 25th visible hour is deliberately not a prediction horizon. It exists so a token
that reaches the complete 24-hour lifecycle can still be observed across the model
boundary without teaching UI age-out as operational death.

Canonical raw database:
  data\axiom_v24_raw.sqlite

The production collector creates exactly one marked collection session and refuses
unmarked existing raw data. Each successful capture must commit one observation per
parsed Axiom card plus the exact UTF-8 clipboard payload (SHA-256 + zlib) atomically.
Failed captures are logged separately and never become token-absence evidence.

Manual setup:
  py -3 -m venv .venv
  .venv\Scripts\python.exe -m pip install --upgrade pip
  .venv\Scripts\python.exe -m pip install -r requirements.txt
  .venv\Scripts\python.exe -m pytest
  .venv\Scripts\python.exe -m profit_taker.collection_admin init --db data\axiom_v24_raw.sqlite --purpose v24_production_raw_collection
  .venv\Scripts\python.exe -m profit_taker.collection_admin status --db data\axiom_v24_raw.sqlite
  .venv\Scripts\python.exe -m profit_taker.axiom_v24 status --db data\axiom_v24_raw.sqlite

Migration from the former 72-hour target:
  - keep valid authoritative raw observations;
  - the first label refresh under this version detects old finalized target metadata
    and rebuilds derived peak/lifecycle labels from the raw observations;
  - do not treat an old 72-hour champion as the new champion. V24 schema and target
    hashes intentionally separate the generations and refuse warm continuation;
  - bootstrap the 24-hour generation only after a mature one-use promotion cohort is
    available under the new 24h lifecycle/outcome timing.

Do not substitute data\live.sqlite when starting the fresh production research
collection. V24 direct CLI defaults are also pinned to data\axiom_v24_raw.sqlite.

No Tesseract, RapidOCR, ONNX Runtime, provider keys, or screenshot tooling is
required. PyTorch is included for the causal sequence challenger; LightGBM and
XGBoost remain the tabular model backends.

This setup is approved for fresh research-data collection and paper evaluation. It
does not constitute approval for unattended real-money execution; that requires
mature one-use promotion cohorts, sealed prospective audit evidence, calibrated
paper-policy performance, and execution/liquidity evidence.
